Este plano é um esboço de um projeto de harness que já está em andamento em vários formatos diferentes, já temos alguns repos aqui como o agnfk, o agenfk-report, o cargroup-skill, o harness-agent-skills e o webmotors-harness-factory que são alguns peços e harness básico completo que servirão para este plano. A idéia é montar um curso e os harness possíveis para a nossa realidade aqui da Webmotors, inicialmente pode ser em html no formato do https://github.com/walkinglabs/learn-harness-engineering (https://walkinglabs.github.io/learn-harness-engineering/en/) usando o system design da Webmortos que está em /home/svslwm/wm/frontend/webmotors.ds.eleanor.tokens e /home/svslwm/wm/frontend/webmotors.design.system.eleanor.

A idéia no curso é apresentar o que é um harness, seu propósito o qual o tipo de harness engineering para cada área e projeto, como por exemplo, um harness de App, deve incluir dois tipos de testes, os já conhecidos do time de QA com suas skills para testes de App e também um harness com as ferramentas de navegação direta no app, desde o build até a validação final controlado por um agente de IA como o Claude code e o Code onde eles conseguem abrir o app, navegar nele e testar tudo.

Uma outra idéia de harness que você também verá na documentação e códigos destes repos/diretórios que te passei, são os harness básico que você pode baixar para dentro do seu projeto, que serve para projetos pequenos, mas os harness maiores que servem para projetos onde muitas equipes trabalham neles.

Uma outra frente deste curso e projeto de harness, é um harness do tipo Cursor com um banco de dados + RAG, que servirá tanto para projetos de programação quanto para projetos de outras áreas onde as pessoas poderão armazenar contextos dos seus próprios projetos como arquivos de negócios, planilhas, imagens, dados da sua própria área para gerenciarem as features que precisam desenvolver com a ajuda do harness e seu poder de contexto com o RAG.
