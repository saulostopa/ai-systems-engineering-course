# Lessons

The theory behind harness engineering, adapted to the Webmotors reality.
Each lesson ends with a `feature-quiz` generated by the skill itself — you learn
harness engineering by consuming the artifacts the harness produces.

## Curriculum

| # | Lesson | Summary |
|---|--------|---------|
| 01 | [Why capable agents still fail](/lectures/lecture-01) | The model is not the product; the environment decides the outcome. |
| 02 | [What a harness really is](/lectures/lecture-02) | Tools, prompt, skills and the closed work loop. |
| 03 | [The repository as system of record](/lectures/lecture-03) | The truth lives in the repo, not in the conversation. |
| 04 | [Why a single instructions file fails](/lectures/lecture-04) | Routing through small files beats piling everything into one giant AGENTS.md. |
| 05 | [Continuity in long-running tasks](/lectures/lecture-05) | State across sessions: progress, handoff and resumption. |
| 06 | [Initialization as its own phase](/lectures/lecture-06) | The harness boot before work begins. |
| 07 | [Excessive autonomy and incomplete delivery](/lectures/lecture-07) | Scope, gates and what is left out. |
| 08 | [Feature lists as harness primitives](/lectures/lecture-08) | `feature_list.json` as the source of truth for what to do. |
| 09 | [Declaring victory too early](/lectures/lecture-09) | Evidence before "done". |
| 10 | [End-to-end tests change the outcome](/lectures/lecture-10) | QA as a mechanical gate, not as intention. |
| 11 | [Observability inside the harness](/lectures/lecture-11) | Measure friction, loops and the cost of each feature. |
| 12 | [Sessions end with clean state](/lectures/lecture-12) | Clean state, handoff and the next session will thank you. |
| 13 | [From manual prompts to autonomous loops](/lectures/lecture-13) | Loop engineering: plan, act, verify, repeat. |
| 14 | [From single loops to graph engineering](/lectures/lecture-14) | Multiple agents, orchestration and the multi-agent future. |
| 15 | [From Markdown to an executable runtime](/lectures/lecture-15) | Instruction vs. contract vs. control; why the agent is not the authority. |
| 16 | [ADK 2 and the three orchestration patterns](/lectures/lecture-16) | Graph, Collaborative and Dynamic — who decides the next step. |
| 17 | [Building a Hard Harness](/lectures/lecture-17) | The `hard-harness/` component: graph, schemas, gates, persistence. |

::: tip How to study
Each lesson ends with the quiz instruction — ask your agent:

```
"quiz me on Lesson 01"   (or the lesson you just read)
```

The `feature-quiz` skill generates the quiz in 4 levels and you validate what you absorbed.
:::
