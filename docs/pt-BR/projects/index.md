# Projetos

A parte prática: cada projeto entrega um harness funcional. Ao final do curso,
você terá um harness completo no seu próprio repositório — ou no da sua área.

Se quiser apenas os pacotes executáveis, use o [catálogo standalone de harnesses](https://github.com/saulostopa/harnesses). O repositório do curso contém as aulas e as explicações; o catálogo contém os projetos executáveis e seus READMEs locais.

| Projeto | Entrega |
|---------|---------|
| [01 · Baseline vs. harness mínimo](/pt-BR/projects/project-01) | A mesma feature com e sem harness; medir a diferença. |
| [02 · Harness básico instalável](/pt-BR/projects/project-02) | O pacote que qualquer projeto pequeno baixa e roda. |
| [03 · Harness de App com QA](/pt-BR/projects/project-03) | E2E Playwright + navegação agêntica com visão. |
| [04 · Harness de domínio](/pt-BR/projects/project-04) | Playbook para games, finanças ou comercial. |
| [05 · Area Copilot com RAG](/pt-BR/projects/project-05) | Contexto da sua área disponível para o agente. |
| [06 · Harness ADK + RAG + Jev](/pt-BR/projects/project-06) | Decisões tipadas roteiam a recuperação em um workflow ADK determinístico. |
| [06B · ADK RAG com PostgreSQL](/pt-BR/projects/project-06-postgres) | Harness de referência com PostgreSQL + pgvector para times maiores. |
| [07 · Harness enterprise](/pt-BR/projects/project-07) | Um orquestrador sem estado gerencia vários repositórios adotados. |

::: tip Como estudar
Os projetos são cumulativos: o 01 cria seu baseline, o 02 empacota o harness,
o 03 adiciona QA, o 04 o domínio e o 05 o contexto da área. Faça na ordem —
cada um assume o anterior.
:::
